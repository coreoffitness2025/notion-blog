# 영상 인식 솔루션 섹션 벤치마크 (2026-10-22)

> 조사 방법: WebFetch(텍스트 추출) + WebSearch. **WebFetch는 이미지와 영상을 못 본다.** 그래서 "시각화 방식"은 페이지 문구, 이미지 파일명, 섹션 제목에서 추정한 것이다. 실제 화면은 브라우저로 한 번 더 봐야 한다.
> 국내 업체는 공식 홈페이지를 찾기 어려워서 기사로 보완했다(아래에 출처 따로 표기).

## 3. CoreVia "영상 인식 솔루션" 섹션이 반드시 보여줘야 할 것

1. **움직이는 증거 하나.** 우리 앱 화면을 녹화해 스켈레톤이 겹친 스쿼트가 횟수를 세는 5~8초 루프를 만든다. 경쟁사도 전부 영상이나 데모가 신뢰의 첫 단추다.
2. **누가 보고 누가 판단하는가.** 회원은 찍히고, 트레이너가 값을 확인하고 기록한다. Physitrack의 "Built for both sides"처럼 두 열로 나눈다.
3. **무엇을 재는지 구체적으로.** 횟수, 관절 각도, 좌우 높이 차(어깨·골반), 기준점 표시. 형용사("정밀한") 대신 측정 항목을 나열한다.
4. **어디까지만 하는지(범위 고지).** Physitrack식 "측정·기록 도구이지 판단 도구가 아니다". 숨기는 문구가 아니라 섹션 하나로 당당하게 둔다.
5. **영상 처리 방식.** 무엇이 기기에 남고 무엇이 서버로 가는지 적는다. ⚠️ 실제 구현을 확인한 뒤에만 쓴다(아래 7번).
6. **도입 형태.** 완성형 앱(트레이너 모드) → 센터 CRM 연동 → (나중에) SDK·API. 지금 실제로 되는 것만 "제공"으로, 나머지는 "협의"로 적는다.
7. **CTA는 체험이나 데모로.** "데모 요청하기" / "트레이너 모드로 직접 측정해보기".

### 솔루션 상세 페이지(선택)
1. 히어로 + 데모 루프 영상
2. **작동 방식 3단계**: ① 카메라가 관절 위치를 찾는다 → ② 앱이 횟수·각도·좌우 차를 계산한다 → ③ 트레이너가 확인하고 기록한다
3. **기능 카드 4장**: 횟수 카운팅 / 실시간 자세 신호 / 정지 자세 측정(정면·측면) / 리포트·회원 기록
4. **화면 두 열**: 트레이너가 보는 화면과 회원이 받는 화면
5. **업종별 카드**: PT·피트니스 센터 / 필라테스·스튜디오 / 시니어·주간보호 운동 프로그램(⚠️ "낙상 예방" 대신 "운동 기록·변화 확인") / 웰니스 앱(SDK는 협의)
6. **측정 범위와 한계(정직 섹션)**: 촬영 조건(뒤 카메라, 다른 사람이 촬영, 전신이 보이도록), 데드밴드(어깨 4°·골반 5° 이하는 "차이 없음"으로 표시) 같은 설계 원칙, 측정하지 않는 것
7. **데이터·프라이버시**
8. **도입 방식**: 앱 그대로 사용 / 센터 CRM 연동 / API·SDK(협의)
9. FAQ("의료기기인가요?" → "아닙니다…")
10. CTA: 데모 요청

## 5. 안전한 표현 가이드(비의료기기)

| 쓰지 않는다 | 이렇게 쓴다 |
|---|---|
| 진단, 검사, 판정, 처방, 치료, 교정 효과 | 측정, 기록, 확인, 참고값, 운동 지도 |
| 거북목·척추측만·골반 틀어짐 "발견" | 어깨·골반의 **좌우 높이 차이 각도**를 표시 |
| 통증 개선, 재활 효과, 낙상 예방 | 운동 수행 기록, 변화 추이 확인 |

| AI가 판단합니다 | 트레이너가 확인합니다 / 판단은 트레이너의 몫입니다 |
| 각도계를 대체 | (쓰지 않는다) |
| 맞춤 운동 처방 | 트레이너가 프로그램을 짜는 데 참고할 기록 |

**고정 면책 문구(회색 한 줄 또는 FAQ, 안내 박스는 쓰지 않는다)**
- "코어비아 영상 인식은 운동 지도를 돕는 측정·기록 도구이며, 의료기기가 아닙니다. 질환을 진단하거나 치료 방향을 제시하지 않습니다."
- "표시되는 각도와 좌우 차이는 촬영 환경에 따라 달라질 수 있는 참고값이며, 트레이너가 확인한 값만 기록됩니다."
- 영문(필요 시): "A measurement and recording tool for exercise coaching — not a medical device, and not a decision-making tool."

## 6. 우리 앱으로 바로 만들 수 있는 시각 자료(고객 0 기준)

| 자료 | 만드는 법 | 용도 |
|---|---|---|
| ① 스쿼트 횟수 카운팅 루프(5~8초, 무음 MP4/WebM) | 실기기 화면 녹화(시뮬레이터로는 카메라 검증 불가). 대표나 지인이 모델, 얼굴 블러 | 히어로 영상 |
| ② 자세 측정 정지 컷 3장: 촬영 가이드 → 관절점·기준선 오버레이 → 결과(좌우 차 각도 + "차이 없음/있음") | 체형분석 흐름 캡처. 시뮬 앨범 경로로 흐름 재현 가능 | 작동 방식 3단계 |
| ③ "트레이너 확인" 화면(기준점 수정, 관찰 칩 선택) | 트레이너 모드 캡처 | "판단은 트레이너" 메시지의 증거 |
| ④ 회원이 받는 체형 리포트 1장 | 시험 계정 리포트 캡처(실제 회원 데이터는 쓰지 않는다) | 결과물 예시 |
| ⑤ 막대 인형 스켈레톤 도식(SVG) | 관절 점·선만 그린 일러스트. 얼굴이 없어 초상권 부담이 없다 | 아이콘·다이어그램 |
| ⑥ 데이터 흐름 도식: 카메라 → 기기 계산 → 숫자만 → 트레이너 | SVG 다이어그램 | 프라이버시 섹션 |

**하지 말 것**
- 고객 로고, 사용자 수, 후기를 만들지 않는다(회원이 없으므로 지어낸 경험이 된다).
- 경쟁사처럼 "분석 n회" 같은 규모 숫자를 쓰지 않는다. 숫자 대신 **"직접 해보기"**로 신뢰를 만든다(KinesteX의 Try on web 패턴).
- 정확도 수치는 `bench.sh` 같은 자체 실험 결과가 있고 조건을 공개할 수 있을 때만 쓴다. 없으면 쓰지 않는다.

## 7. 게시 전에 확인할 것(미확인 사항)
- **영상과 사진의 처리 위치**: 체형분석 사진이나 프레임이 서버(Storage)에 올라가는지, 기기에서만 처리하는지. 메모리 기록에 "remote 엔진"과 "저장 화이트리스트"가 있어서, "영상을 저장하지 않습니다" 문구는 **구현을 확인하기 전에는 쓰지 않는다.** 저장한다면 "회원 동의 후 촬영 사진은 회원 기록에만 저장"처럼 사실대로 적는다.
- 횟수 카운팅이 지원하는 운동 목록과 개수(카드에 숫자를 넣을지).
- SDK·API를 실제로 제공할 수 있는지. 안 되면 "도입 방식"에서 빼거나 "협의"로 적는다.
- Recovery(재활) 앱과 같은 페이지에 둘지. 재활 문맥이 섞이면 의료로 오인될 위험이 커진다.
